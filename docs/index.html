Label a container. Get DNS.

Label a container consul=yes and publish a port: the registrator registers it in Consul, so Consul's DNS answers for it - A, AAAA, SRV and PTR - and removes it when the container stops.

How it works

Containerslabelled consul=yes, ports published
→
Registratorfollows the runtime's events, compares, registers
→
Consul agentin the same container, on the host's network
→
Consul serverskept in step by the agent
  • For every running container labelled consul=yes: one Consul service instance per published port and address family.
  • It compares on every change the runtime reports, and every minute in case one was missed; when the runtime restarts, it follows it again.
  • It only touches the services it registered (registered-by = docker-consul-registrator in their metadata). Only consul=yes counts - consul=true is reported, not registered.
  • Health: a container's own health check becomes a TTL check (critical while starting or unhealthy, passing when healthy). Other TCP ports get a TCP check.

What DNS answers

For a container named web publishing port 8080 on docker1, in the domain dmarts.app:

QueryAnswer
web.service.dmarts.app Athe host's IPv4 address
web.service.dmarts.app AAAAthe host's IPv6 address, when the port is published on IPv6 too
web.service.dmarts.app SRV
_web._tcp.service.dmarts.app SRV		port 8080, one target per address family
_dns._udp.service.dmarts.app SRVthe UDP ports of dns - each service is tagged with its protocol
PTR of the host's IPv4 addressthe host's node name, docker1.node.dmarts.app
PTR of the host's IPv6 addressa service on it - Consul names nodes for their main address only

Service names

  • a Swarm task: its service's name (shop_web becomes shop-web);
  • a Compose container: <project>-<service>;
  • otherwise the container's name;
  • more than one port: one service per port - web-80, web-443.

Names are always DNS labels. Consul's names always hold .service.: a service is web.service.dmarts.app, not web.dmarts.app.

Run it

It needs the host's network and the runtime's socket. With --agent - the image's default - it starts its own Consul agent; give the agent its configuration (servers to join, gossip key, tokens) in /consul/config, and its state a volume.

A single host

docker run -d --name consul-registrator --network host --restart unless-stopped \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v consul-agent-data:/consul/data \
  -v /etc/consul-agent:/consul/config:ro \
  docker-consul-registrator:VERSION \
  --agent --token-file /consul/config/registrator.token --domain dmarts.app

A Swarm, one task per node

docker service create --name consul-registrator --mode global --network host \
  --mount type=bind,src=/var/run/docker.sock,dst=/var/run/docker.sock \
  --mount type=volume,src=consul-agent-data,dst=/consul/data \
  --config src=consul-agent,target=/consul/config/agent.hcl \
  --secret src=consul-agent-secrets,target=/consul/config/secrets.hcl \
  --secret src=consul-registrator-token,target=registrator.token \
  docker-consul-registrator:VERSION \
  --agent --token-file /run/secrets/registrator.token --domain dmarts.app

Swarm's routing-mesh ports can only be read on a manager. On workers, publish with mode=host: each task is then registered at its own node.

The agent's configuration

# /consul/config/agent.hcl
datacenter  = "dc1"
retry_join  = ["consul-server-1", "consul-server-2", "consul-server-3"]
client_addr = "127.0.0.1"
dns_config { only_passing = true }
acl {
  enabled        = true
  default_policy = "deny"
}

# /consul/config/secrets.hcl - keep it secret
encrypt = "<gossip key>"
acl {
  tokens {
    agent   = "<agent token>"
    default = "<DNS read token>"
  }
}

Runtimes

Mount the runtime's socket at its usual path and it is found. The socket is known by how it answers, not where it is: the Engine API's /_ping for Docker and Podman, containerd's gRPC version call for containerd.

RuntimeMount
Docker-v /var/run/docker.sock:/var/run/docker.sock
Podman, rootful-v /run/podman/podman.sock:/run/podman/podman.sock
Podman, rootless-v $XDG_RUNTIME_DIR/podman/podman.sock:/run/podman/podman.sock
containerd-v /run/containerd/containerd.sock:/run/containerd/containerd.sock --uts host

containerd knows nothing of published ports: they are read from the label nerdctl writes, so containers made with nerdctl are registered. It reads one namespace, default unless --containerd-namespace says otherwise.

The bundled Consul agent

The registrator registers with the agent in its own container only; the agent's anti-entropy keeps the servers in step. It starts the agent with what it works out from the host:

  • node name - the host's name;
  • address - the host's Swarm address, else the default route's;
  • IPv6 - the stable global address beside it, for AAAA answers;
  • DNS domain - --domain, made the agent's own domain (so PTR answers name things in it), with consul kept as its alternative.

Without --agent it registers with the agent --consul names, and with --domain it checks that agent serves the domain - and says what to add to its configuration when it does not.

Consul ACLs

The registrator

service_prefix "" {
  policy = "write"
}
agent_prefix "" {
  policy = "read"
}

The bundled agents

node_prefix "" {
  policy = "write"
}
service_prefix "" {
  policy = "read"
}

DNS (the agents' default)

node_prefix "" {
  policy = "read"
}
service_prefix "" {
  policy = "read"
}
query_prefix "" {
  policy = "read"
}

The registrator reads its token from --token-file only, and again whenever the file changes.

Security

  • A runtime's socket is root on its host: run the registrator where you would run root. For Docker, a read-only socket proxy can stand in front (--socket tcp://proxy:2375).
  • Whatever comes in is checked first - flags, the runtime's names, labels, ports and addresses, Consul's answers, the token file - and text from outside is cleaned before it reaches a log line.
  • The ACL token is never taken from the command line, and never logged.
